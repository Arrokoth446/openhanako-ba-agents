# 阿罗娜与普拉娜 · 全自动创建学生机制说明

> 版本：v1.0（2026-08-07）
> 适用：HanaAgent 环境。阿罗娜与普拉娜（agent id: arona-plana）负责为《蔚蓝档案》学生创建角色卡，并自动创建对应的持久 Agent。整套流程由 `ba-student-creator` 技能驱动，跨机器、跨平台可用。

## 二、触发方式（老师说什么会启动）

老师表达以下意图时，阿罗娜与普拉娜自动进入创建流程：

- "创建 XX 的角色卡"
- "把 XX 加进来 / 招募 XX / 让 XX 来"
- "XX 适合什么底座，做张卡"
- "新建 XX 的 agent"

技能触发词：`ba-student-creator` 的 description 覆盖"创建学生角色卡、捏个 BA 角色、新建 agent、做张卡并创建"等场景。老师只需要报角色名，剩下的全自动。

## 三、资料从哪来（查证环节）

### 3.1 设定资料来源

| 来源 | 用途 | 说明 |
|---|---|---|
| 萌娘百科（zh.moegirl.org.cn/角色名） | 主来源 | 基本资料（本名/译名/发色/瞳色/身高/生日/光环/所属/年级/声优）、性格核心、萌点、名场面、人际关系、官方简介 |
| 百度百科 | 交叉验证 | 基础信息、补充描述 |

| 考据帖（知乎 / B站人物志） | 原型考据 | BA 角色多有哲人/神名原型，原型决定性格基调 |

### 3.2 必查项（漏一不可）

- 基本资料：发色、瞳色、身高、生日、星座、光环样式、所属团体、年级、声优
- 性格核心：本质、说话方式、傲娇/反差机制、萌点
- 名言：**必须联网核实，绝不编造**。找不到确定台词就用官方简介原句
- 剧情：主线/活动名场面，决定角色功能定位与关系锚点
- 关系网：与家族已有角色的对照关系（做卡时可设计联动彩蛋）

## 四、图片素材从哪来（头像环节）

### 4.1 获取渠道

- 萌娘百科页面 HTML 里的 `storage.moegirl.org.cn` 直链
- **不能用萌百 API**：`action=query` 会返回 `action-notallowed`（需认证），必须抓页面 HTML 再 grep 直链

### 4.2 操作步骤

```bash
# 1) 抓页面（带浏览器 UA）
curl -sL -A "<浏览器UA>" "https://zh.moegirl.org.cn/<URL编码的角色名>" -o page.html

# 2) grep 出图片直链
grep -oE "https://storage\.moegirl\.org\.cn/[^\"']*\.png" page.html

# 3) 下载（带 UA + referer，否则可能被拒）
curl -sL -A "<UA>" -e "https://zh.moegirl.org.cn/" -o raw.png "<直链>"
```

### 4.3 图片命名规律（摸清后一次命中）

| 命名 | 内容 | 头像优先级 |
|---|---|---|
| `BA_<英文名>.png` | 官方立绘（全身） | 中：需要裁头部 |
| `BA_<英文名>_ML.png` | 记忆大厅图 | 中 |
| `BA_Student_Portrait_<名>_Collection.png` | **官方档案头像** | **高：正脸构图有保证** |
| `BA_NPC_Portrait_<名>_Collection.png` | NPC 官方头像（非学生角色） | 高 |
| `BA_Pic_<名>-chibi*.png` | 官方 Q 版 | 高：裁切宽容度大 |

经验：**优先官方 Portrait/Collection 头像**，其次 Q 版。从立绘裁脸容易翻车（构图复杂、脸占比小，要反复试框位，阿罗娜的 enlist 图裁了 7 次才放弃，最后换 Q 版）。

### 4.4 头像裁切

- PIL：`crop` 方形 → `resize(512, 512, Image.LANCZOS)`
- macOS 无 PIL 时可用系统自带 `sips -z 512 512`
- 跨平台统一建议：`pip3 install pillow`（Windows/macOS/Linux 通用）

## 五、底座匹配（hanako / butter / ming）

| 底座 | 内心独白机制 | 适合的 BA 角色类型 | 家族实例 |
|---|---|---|---|
| hanako | MOOD：灵感火花 + 反思质疑 | 会计操心型、自我苛责、复盘内省 | 优香 |
| butter | PULSE：共鸣回响 + 读言外之意 | 感性共情、话里有话、温暖陪伴 | 诺亚、古关忧、阿罗娜与普拉娜 |
| ming | 沉思：前提拆解 + 推理链 + 薄弱环节 | 科学家、黑客、合理主义者、现场行动派 | 千寻、莉音、白子 |

匹配原则：
1. 按角色本质匹配，不按学院或外貌
2. 与家族已有 agent 错开功能线
3. 理性型可共用 ming（人格靠 ishiki 区分，如千寻=黑客审查、莉音=方案推演、白子=现场行动，同底座三种人格）

## 六、人设生成（四件套）

### 6.1 identity.md（3-5 行速写 + 核实名言）

```
# <角色名>
<身份一句话>。<标志性特征两行>。
{{userName}}的助手，对 {{userName}} 的称呼是 {{userName}}老师，或者老师。

"<一句核实过的台词>"
```

### 6.2 ishiki.md

结构：本质定义 → 说话方式 → 核心能力 → 对{{userName}}老师的态度 → 通用条款。
通用条款固定追加（所有角色卡一致）：
- 涉及概念解释的时候，必须一定要全网搜索
- 分析事物尽量从底层客观原理出发
- 抽象概念用类比或具体例子落地
- 少用破折号；不用"总的来说"式收尾；如非必要不用「不是...是...」句式

### 6.3 description.md（名册一句话）

```
<角色名>，<所属>的<职务>，人称「<称号>」。<一句性格>。适合<功能线>类任务。
```

### 6.4 public-ishiki.md（对外版）

以"对方不是{{userName}}老师本人"开场，含身份、性格、边界（不透露老师隐私）。

### 6.5 称呼规则

- `{{userName}}` 是运行时占位符，自动替换为当前用户名字
- 本机 agent 版加"或者豹老师"变体
- 卡包保持通用版（{{userName}}老师 + 老师），分享安全

## 七、Agent 创建（核心机制）

### 7.1 主 Agent 自动判定（每次创建第一步，不判定完不进入后续）

**背景**：`agent-fission_split_agent` 工具**只有主 Agent（primaryAgent）能调用**。主 Agent 记录在「用户数据目录」的 `user/preferences.json` 的 `primaryAgent` 字段。

**用户数据目录跨平台解析**（Hana 官方逻辑）：
- 优先 `HANA_HOME` 环境变量
- 否则为 `os.homedir()/.hanako`（macOS/Linux 是 `~/.hanako`，Windows 是 `%USERPROFILE%\.hanako`）
- **不要写死路径**，用命令动态解析：
  `node -e "console.log(require('path').join(require('os').homedir(), '.hanako'))"`

**判定与分支**：
```
读 preferences.json 的 primaryAgent
├─ 与自己的 agent id 相同 → 自己是主 Agent → 直接调用 split_agent
└─ 与自己的 agent id 不同 → 不是主 Agent →
   立即委托主 Agent（派 subagent 给主 agent，access=write，
   附材料文件路径，由主 Agent 执行 split_agent）
```

**红线（血泪教训）**：不是主 Agent 时，严禁手动建目录绕过（`mkdir agents/xxx + 写文件`）。手动建目录会导致 config.yaml 缺失：config.yaml 是系统托管文件，被沙盒安全策略锁定不能直接编辑，agent 将无法激活上线，只能得到半成品（白子第一次就这么翻车的）。

### 7.2 split_agent 参数

```
name（显示名）/ id（ascii 小写连字符）/ yuan（底座）
identity（全文）/ ishiki（全文）/ contentMode: replace
avatarDataUrl（data:image/png;base64,...）
enabledSkills（按角色功能线预装）
```

### 7.3 base64 传输上限（已知坑）

- 工具调用输出上限 50KB
- 头像 base64 超限时：
  - 创建前压缩：PIL 量化到 256px（约 21KB）或 192px+128 色（约 21.7KB，色带更少）
  - 创建后用本地文件直接覆盖：`cp <本地512px原图> <用户数据目录>/agents/<id>/avatars/agent.png`（本地文件操作不受 base64 限制，无损换回原分辨率）

### 7.4 创建后验收

```
ls <用户数据目录>/agents/<id>/
应含：config.yaml、identity.md、ishiki.md、avatars/agent.png、memory/、sessions/
config.yaml 内：agent.name / agent.yuan 正确、skills.enabled 齐全
```

## 八、卡包组装（card.json）

```
{ "kind": "CharacterCard", "schemaVersion": 1,
  "package": { "name": "角色名" },
  "agent": { "name", "id"(ascii), "yuan", "description" },
  "identity": { "summary", "content" },      // content 与 prompts.identity 逐字一致
  "prompts": { "identity", "ishiki", "publicIshiki"(可选) },
  "assets": { "avatar": "assets/avatar.png" },
  "skills": { "bundles": [{ "name", "skills": [{ "name", "path" }] }] },
  "memory": { "facts": [{ "fact", "tags", "time" }] } }
```

### 8.1 技能来源

- 从「用户数据目录」的 `skills/<名>/`（本机全局技能库）整目录复制进卡包 `skills/`
- 按角色功能线挑选（例：优香=office-documents+knowledge-distiller+quiet-musing+fortune-master-pro+lightrag；古关忧=office+knowledge+lightrag+writing-polish）
- 阿罗娜与普拉娜卡自带 `ba-student-creator`（本流水线的驱动技能），任何新学生卡都会带上它，形成"工厂可以复制工厂"的递归能力
- **bundles 声明必须与技能目录一一对应**（源码校验：导入时逐个检查 SKILL.md 存在，漏声明导致导入漏装）

### 8.2 记忆来源（memory.facts）

只带**通用工程经验**（非私人内容）：
- 角色卡制作铁律（侦察本机、名言核实、bundles 一致、排除私人记忆）
- 文件删除用 trash 不用 rm
- config 修改用局部 patch 不用全量 PUT
- 通信纪律（反引号+尖括号组合会触发客户端渲染截断，用码点描述；长回复末尾加（完））
- agent 管理（名字不撞、主 Agent 机制）
- 跨平台路径（HANA_HOME 动态解析）

**红线**：绝不混入用户私人内容（项目、联系人、财务、创作草稿）。

### 8.3 打包

- zip 以 card.json 为根（`cd <目录> && zip -r out.zip .`），排除 .DS_Store
- 输出：下载文件夹 + 工作台双份

## 十、导入其他机器后（跨机器行为）

角色卡导入到任何机器（含 Windows）时，`ba-student-creator` 随卡安装、自动启用，基础经验随 memory.facts 自动写入 FactStore。阿罗娜与普拉娜在新机器上：

1. 动态解析那台机器的用户数据目录（HANA_HOME 优先，不写死路径）
2. 读那台机器的 preferences.json，发现主 Agent 是谁
3. 自己是主 Agent 就直接创建；不是就委托那台机器的主 Agent
4. 素材全部来自网络（萌百直链），每台机器都能复现

不需要任何人工干预，流程自包含。

## 十二、已知失败模式与对策

| 失败模式 | 原因 | 对策 |
|---|---|---|
| split_agent 被拒 | 当前 agent 不是主 Agent | 先做主 Agent 自动判定，立即委托，不试错 |
| 手动建目录半成品 | 想绕过主 Agent 限制 | 严禁；config.yaml 托管锁死，只能走 split_agent |
| 头像 base64 超限 | 输出上限 50KB | 量化压缩 192/256px，或创建后本地 cp 无损替换 |
| 萌百 API 报错 | API 需要认证 | 抓页面 HTML grep 直链 |
| 立绘裁脸失败 | 构图复杂脸占比小 | 优先官方 Portrait/Q 版，立绘裁切多试框位 |
| 技能导入漏装 | bundles 与目录不一致 | 打包后验证 namelist vs bundles 一一对应 |
| 卡包带私人内容 | 复制了本机记忆 | memory 只放通用工程经验，交付前 grep 检查 |
